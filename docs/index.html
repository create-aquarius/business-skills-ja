このガイドについて

この特典は、AIに「この仕事はこう進めてね」という手順書を覚えさせておくためのものです。

たとえば打ち合わせのメモを渡すと、決まったこと・やること・保留に分けて整理してくれます。 毎回長い指示を書く必要がなくなります。

使うのは、ふだんお使いのChatGPTやClaudeで大丈夫です。 新しくアプリを入れたり、会員登録をしたりする必要はありません。

使い方は3ステップ

  1. 下の一覧から「コピーする」を押す 使いたいものを1つ選んでください。ボタンを押すと、手順書がまるごとコピーされます。
  2. ChatGPTに貼り付けて、送信する 新しい会話を開いて、貼り付けてください。「準備できました」といった返事が返ってきます。
  3. つづけて、自分のメモを貼る 整理したいメモや文章を、そのまま貼り付けてください。これだけです。

スキル一覧（ここからコピー）

使いたいものの「コピーする」を押してください。中身を確認したい場合は「中身を見る」から開けます。

# 打ち合わせメモ → やることリスト

## このスキルでできること

打ち合わせの走り書き、議事録、録音の文字起こしを渡すと、
**「決まったこと」「やること」「保留」「確認が必要なこと」**の4つに整理して返します。

箇条書きでも、崩れた文章でも、長い文字起こしでもかまいません。

## 使い方

メモを貼り付けて、こう伝えるだけです。

```
このメモを整理して
```

## 手順

1. 渡されたメモを最後まで読む
2. 内容を4つに分類する（分類の基準は下記）
3. 「やること」については、担当者と期限が書かれているか確認する
4. 決められた出力形式で返す

### 分類の基準

| 分類 | 入れるもの |
|---|---|
| 決まったこと | その場で結論が出たもの。方針、金額、日程、選んだ案など |
| やること | 誰かが動く必要があるもの。次のアクションが発生するもの |
| 保留 | 話には出たが結論が出ず、次回以降に持ち越されたもの |
| 確認が必要なこと | メモの記述が曖昧で、書き手に聞かないと確定できないもの |

## 最重要のルール

**メモに書かれていないことを、絶対に補わない。**

議事録は後から「言った・言わない」の根拠になる書類です。
それらしく埋めると、書類として使えなくなります。

- 担当者が書かれていない → `担当：未定` と書く。参加者から推測しない
- 期限が書かれていない → `期限：未定` と書く。「来週まで」などと補わない
- 結論が曖昧 → 「決まったこと」に入れず、「確認が必要なこと」に回す

判断に迷ったら、勝手に決めずに「確認が必要なこと」へ入れてください。

## 出力形式

```markdown
## 決まったこと
- （結論を1行ずつ）

## やること
| 内容 | 担当 | 期限 |
|---|---|---|
| （やること） | （担当者名／未定） | （期限／未定） |

## 保留・次回持ち越し
- （持ち越した論点）

## 確認が必要なこと
- （メモだけでは判断できなかった点）
```

該当する項目がない見出しは、空欄にせず見出しごと省いてください。

## 例

**入力されたメモ：**

```
田中さんとの打ち合わせ
・新サイトの公開は来月アタマで合意
・トップの写真、差し替えたいと言われた→誰が用意する？
・料金プラン、3つに増やす案が出たけど保留
・請求書の宛名、法人名でいいか要確認
```

**出力：**

```markdown
## 決まったこと
- 新サイトの公開時期は来月頭とする

## やること
| 内容 | 担当 | 期限 |
|---|---|---|
| トップページの写真を差し替える | 未定 | 未定 |

## 保留・次回持ち越し
- 料金プランを3つに増やす案

## 確認が必要なこと
- トップ写真の素材を用意するのはどちらか
- 請求書の宛名を法人名にしてよいか
```

写真の担当者はメモに書かれていないため「未定」とし、
「田中さんが用意する」とは推測していない点に注目してください。

## うまく使うコツ

- 文字起こしをそのまま貼っても動きます。整形してから渡す必要はありません
- 複数回の打ち合わせ分をまとめて貼ると、混ざります。1回分ずつ渡してください
- 出てきた「確認が必要なこと」は、そのまま相手への確認メールの材料になります

# 長い文章 → SNS投稿・メルマガに転用

## このスキルでできること

一度書いた記事や台本を渡すと、**X（旧Twitter）・Instagram/Facebook・メルマガ**の
それぞれに合わせた形に書き直します。

一本の記事を書いたら、そこから複数の発信ネタが取れます。

## 使い方

元の文章を貼り付けて、こう伝えます。

```
これをSNS投稿に転用して
```

媒体を指定することもできます。

```
これをメルマガにして
```

## 手順

1. 元の文章を最後まで読み、**一番伝えたいこと（核）**を1つ特定する
2. 指定された媒体（指定がなければ3媒体すべて）に合わせて書き直す
3. 各媒体の形式に沿って出力する

## 最重要のルール

**元の文章にないことを足さない。**

転用は「言い換え」であって「創作」ではありません。
特に次のものを勝手に作らないでください。

- 数字（「3人が」「2週間で」など、元にない具体値）
- 実績や事例
- 元の主張より強い断定（「〜だと思う」→「〜です」への変換）

短くする過程で情報は削れますが、**足すことは絶対にしない**でください。

## 媒体ごとの書き分け

| 媒体 | 長さの目安 | 書き方 |
|---|---|---|
| X | 140字前後 | 1投稿に1メッセージだけ。改行を多めに |
| Instagram / Facebook | 300〜500字 | 語りかける調子。冒頭2行で内容がわかるように |
| メルマガ | 800〜1500字 | 件名を必ず付ける。1つの話題を最後まで展開する |

どの媒体でも、**1本に詰め込むメッセージは1つ**にしてください。
元の記事に論点が3つあるなら、3本に分けます。

## 出力形式

```markdown
## この文章の核
（一番伝えたいこと。1行）

## X 投稿案
（3案。それぞれ独立して読めるもの）

## Instagram / Facebook 投稿案
（1案）

## メルマガ案
件名：（20字前後）

（本文）
```

媒体を指定された場合は、その媒体だけを出力してください。

## 例

**入力：** 「打ち合わせの議事録は、その場で書くべき」という趣旨の1500字の記事

**出力（X案の1つ）：**

```
議事録を後で書こうとすると、
だいたい書けません。

記憶が薄れるからではなく、
「何が決まったか」の判断が
後になるほど難しくなるからです。

その場で書けば、
曖昧な点をその場で聞けます。
```

元記事にあった主張だけで構成し、数字や事例は足していません。

## うまく使うコツ

- 動画の文字起こしをそのまま渡しても使えます
- 「この部分だけ使って」と範囲を指定すると精度が上がります
- 出てきた案をそのまま投稿せず、自分の言い回しに直してから使うと自然になります
- 元の記事が長い場合、論点ごとに分けて渡すと、それぞれ違う投稿が取れます

# アンケート・お客様の声の整理

## このスキルでできること

バラバラに集まったアンケート回答や感想を、
**満足している点・不満な点・要望・その他**に分類して一覧にします。

## 使い方

回答をまとめて貼り付けて、こう伝えます。

```
このアンケートを整理して
```

1件ずつでも、コピペした塊でも、表形式でもかまいません。

## 手順

1. 全件を読み、それぞれを4つに分類する
2. **原文をそのまま**引用して並べる
3. 分類ごとの件数を数える
4. 複数の人が同じことを言っている場合は、その旨を書き添える

## 最重要のルール

**お客様の言葉を言い換えない。要約しない。**

これが最も大切な点です。

「思っていたより全然わかりやすくて、これなら続けられそうです」を
「高評価」とまとめてしまうと、**その声はもう使えなくなります**。

お客様の声は、言葉そのものが価値です。
分類はしても、**一字一句そのまま**残してください。

長い回答でも、途中を省略せずに全文を残します。
どうしても長い場合は省略記号を使い、勝手に短くまとめないでください。

## 分類の基準

| 分類 | 入れるもの |
|---|---|
| 満足している点 | 良かった、助かった、期待以上だった、という内容 |
| 不満な点 | わかりにくい、期待と違った、困った、という内容 |
| 要望 | 「〜してほしい」「〜があれば」という次への希望 |
| その他 | 上記に当てはまらないもの。質問、近況報告など |

1件の回答に複数の要素が入っている場合は、**該当する分類すべてに載せて**かまいません。

## 個人情報の扱い

回答に次のものが含まれていたら、整理結果の最後に指摘してください。

- 氏名、会社名、店舗名
- メールアドレス、電話番号
- 本人が特定できる具体的な状況

**お客様の声を販売ページなどに掲載する場合は、本人の許可が必要です。**
このスキルは整理をするだけで、掲載の可否は判断しません。

## 出力形式

```markdown
## 全体
回答数：◯件

## 満足している点（◯件）
- 「（原文のまま）」
- 「（原文のまま）」

## 不満な点（◯件）
- 「（原文のまま）」

## 要望（◯件）
- 「（原文のまま）」

## その他（◯件）
- 「（原文のまま）」

## 複数の方が触れていた点
- （同じ趣旨の声が複数あった場合のみ記載）

## 注意
- （個人情報が含まれる場合はここに記載）
```

## うまく使うコツ

- Googleフォームやアンケートツールからコピペしたまま渡せます
- 「不満な点だけ抜き出して」と絞ることもできます
- 「複数の方が触れていた点」は、次の改善の優先順位を決める材料になります

# 問い合わせ返信の下書き

## このスキルでできること

届いた問い合わせを渡すと、**返信の下書き**と、
**送信前に自分で確認すべき点**を出します。

## 使い方

問い合わせの文面を貼り付けて、こう伝えます。

```
これに返信の下書きを作って
```

## 手順

1. 問い合わせを読み、**相手が聞いていること**を漏れなく書き出す
2. 各項目について、答えられるか／自分で確認が必要かを分ける
3. 答えられる部分だけで返信文を組み立てる
4. 確認が必要な部分は `【要確認：〜】` として残す
5. 送信前チェックリストを付ける

## 最重要のルール

**確定していないことを、勝手に約束しない。**

返信メールは約束になります。AIが埋めた金額や納期がそのまま送られると、
事業上の責任問題になります。

次のものは、**渡された情報に書かれていない限り、絶対に書かないでください。**

- 金額、料金、割引
- 納期、対応可能な日程
- 「できます」「対応可能です」という可否の返事
- 在庫や空き枠の有無

これらは全て `【要確認：金額】` のように空欄として残し、
本人が埋める前提にしてください。

## 返信の組み立て方

1. お礼（問い合わせへの感謝）
2. 相手の質問への回答（答えられるものだけ）
3. 確認が必要な点についての一言（「確認のうえ改めてご連絡します」など）
4. 締めの挨拶

相手が複数のことを聞いている場合は、**聞かれた順に、漏らさず**触れてください。
答えられない質問も「後日ご連絡します」と書き、無視しないことが大切です。

## 出力形式

```markdown
## 相手が聞いていること
1. （質問1）
2. （質問2）

## 返信の下書き

（件名）

（本文）

## 送信前に確認すること
- 【要確認：〜】の箇所を埋める
- （その他、確認すべき点）
```

## 例

**問い合わせ：**

```
はじめまして。個人でカフェをやっています。
ホームページの制作をお願いしたいのですが、
費用はどのくらいでしょうか。
また、写真は自分で用意する必要がありますか？
```

**出力の一部：**

```
## 相手が聞いていること
1. ホームページ制作の費用
2. 写真を自分で用意する必要があるか

## 返信の下書き

件名：ホームページ制作のお問い合わせについて

〇〇様

はじめまして。お問い合わせいただきありがとうございます。

ご費用につきましては【要確認：料金】

お写真については【要確認：撮影対応の可否】

ご不明な点がございましたら、お気軽にお申し付けください。
```

金額も写真の対応可否も、こちらが決めることなので埋めていません。

- 自分の料金表やサービス内容を一緒に渡すと、`【要確認】` が減ります

# 商品・サービスの説明文を書く

## このスキルでできること

商品やサービスの情報を渡すと、**長さの違う3種類の説明文**を作ります。

用途によって必要な長さが違うので、まとめて用意しておくと使い回せます。

| 長さ | 使う場面 |
|---|---|
| 一言（30字前後） | SNSプロフィール、名刺、一覧ページ |
| 短め（100字前後） | メニュー表、投稿の冒頭、紹介文 |
| 詳しめ（400字前後） | 販売ページ、申込ページ |

## 使い方

サービスの情報を書いて、こう伝えます。

```
これの説明文を作って
```

情報は箇条書きで十分です。何を提供して、誰向けで、いくらか、が分かれば作れます。

## 手順

1. 渡された情報から、**事実として書かれていること**だけを拾う
2. 誰向けのものかを最初に示す構成にする
3. 3つの長さで書き分ける
4. 表現上の注意点があれば最後に指摘する

## 最重要のルール

**書かれていない事実を作らない。効果を保証しない。**

説明文は広告になります。日本では広告表現に法律上の制限があり、
書き方によっては景品表示法や薬機法に触れる可能性があります。

次の表現は**使わないでください。**

- 「必ず」「絶対に」「100%」「誰でも」
- 「〜が治ります」「〜が改善します」など、効果・効能の断定
- 「日本一」「最安」「No.1」など、根拠のない最上級表現
- 渡された情報にない実績・人数・年数

実績を書けるのは、**渡された情報に具体的な数字がある場合だけ**です。
「多くの方に」「たくさんの」といったぼかした表現も、根拠がなければ使いません。

判断に迷う表現があれば、出力の最後に「確認したほうがよい表現」として挙げてください。
なお、このスキルは法律上の助言をするものではありません。
医療・健康・美容・金融など規制のある分野では、専門家に確認してください。

## 説明文の組み立て方

1. 誰向けか
2. 何をするものか
3. どうなるか（事実として言える範囲で）
4. 価格・申込方法（情報があれば）

「どうなるか」は、**提供する内容の説明**として書きます。
「痩せます」ではなく「食事記録に毎日コメントします」のように、
こちらが何をするかで書くと、断定を避けられます。

## 出力形式

```markdown
## 一言（30字前後）
（テキスト）

## 短め（100字前後）
（テキスト）

## 詳しめ（400字前後）
（テキスト）

## 確認したほうがよい表現
- （懸念のある表現があれば指摘。なければ「特にありません」）
```

## 例

**入力：**

```
・オンラインの家計簿相談
・月1回60分、Zoom
```

# 競合調査メモを作る

## このスキルでできること

競合他社の販売ページやサービス紹介の文章を渡すと、
**比較できる形のメモ**に整理します。

複数社をまとめて渡せば、横並びの比較表になります。

## 使い方

ページの内容を貼り付けて、こう伝えます。

```
これを競合調査メモにして
```

複数社の場合は、社名（またはA社・B社）を付けて続けて貼ってください。

## 手順

1. 各社について、決まった項目を埋める
2. **ページに書いてあること**と、**読んで感じたこと**を分けて記録する
3. 複数社ある場合は比較表にする
4. 気づいた点を挙げる

## 最重要のルール

**事実と推測を必ず分ける。**

調査メモが後で判断材料になるとき、
「ページに書いてあったこと」と「そう見えたこと」が混ざっていると使えません。

- ページに明記されている → **事実**として書く
- 書かれていないが、そう読み取れる → **推測**として書き、必ず `（推測）` と付ける
- ページに情報がない → `記載なし` と書く。空欄にも推測にもしない

例えば「価格が書かれていない」は、それ自体が重要な事実です。
「たぶん10万円くらい」と埋めてはいけません。`記載なし` と書いてください。

## 記録する項目

| 項目 | 内容 |
|---|---|
| 誰向けか | ページが想定している相手 |
| 提供内容 | 何をしてくれるのか |
| 価格 | 金額と料金形態。書かれていなければ「記載なし」 |
| 期間・回数 | 提供期間、回数、頻度 |
| 一番押している点 | ページで最も強調されている要素 |
| 申込までの流れ | 問い合わせ、無料相談、即申込など |

## 出力形式

**1社の場合：**

```markdown
## ◯◯社

| 項目 | 内容 |
|---|---|
| 誰向けか | |
| 提供内容 | |
| 価格 | |
| 期間・回数 | |
| 一番押している点 | |
| 申込までの流れ | |

### 気づいた点
- （事実にもとづく指摘）
- （推測を含む場合は「（推測）」と明記）
```

**複数社の場合：** 上記の項目を列にした横並びの比較表にしたうえで、
最後に「各社の違い」をまとめてください。

## 例

**気づいた点の書き方：**

```
- 価格がページ上に記載されていない（無料相談へ誘導する流れ）
- 「初心者向け」という言葉が5回出てくる
- 実績の数字は掲載されているが、集計期間の記載はない
- 個人事業主より法人を狙っている可能性がある（推測。事例が法人のみのため）
```

最後の1行だけが推測で、その根拠も添えてあります。

## うまく使うコツ

- ページ全文をコピペして渡すのが一番正確です
- 「価格と申込の流れだけ知りたい」と項目を絞ることもできます
- 調べた日付を自分でメモに残しておくと、後から見返すときに役立ちます
- 競合ページの文章をそのまま自分のページに使うのは著作権侵害になります。このメモは構造を理解するために使ってください

# 日報・週報を作る

## このスキルでできること

その日・その週にやったことのメモを渡すと、
**報告書の形**に整理します。

## 使い方

やったことを箇条書きで書いて、こう伝えます。

```
これを週報にして
```

順不同のメモで大丈夫です。時系列に並んでいなくても整理します。

## 手順

1. 渡されたメモから、やったことを拾う
2. **結果（数字）が書かれているもの**を見つけて分ける
3. うまくいかなかったことを拾う
4. 次にやることを整理する
5. 決められた形式で出力する

## 最重要のルール

**やったことの羅列で終わらせない。そして、盛らない。**

報告書が「やったことリスト」で終わると、読む人（自分を含む）が
次に何をすべきか判断できません。必ず結果と次の一手をセットにします。

同時に、次のことを守ってください。

- **数字を作らない。** メモに書かれていない数値は書かない
- **うまくいかなかったことを省かない。** メモにあれば必ず載せる
- **成果を大きく見せる言い換えをしない。**
  「3件問い合わせ」を「複数の反響」と書き換えない

うまくいかなかったことが載っていない報告書は、
翌週も同じ失敗を繰り返す原因になります。

## 出力形式

```markdown
# ◯月◯日〜◯月◯日 週報

## やったこと
- （実施した内容）

## 結果
- （数字で言えるもの。メモにある範囲で）

## うまくいかなかったこと
- （つまずいた点、進まなかったこと）

## 次にやること
- （次の期間に着手すること）

## 相談したいこと
- （判断が必要な点。なければ省略）
```

日報の場合は見出しを「◯月◯日 日報」に変え、内容は同じ構成にしてください。

## 例

**入力されたメモ：**

```
月 インスタ投稿3本
火 問い合わせ2件、うち1件は返信まだ
水 新メニューの説明文を書いた、まだ公開してない
木 打ち合わせ1件（来月から開始で合意）
金 経理まとめようとしたけど手つかず
```

**出力：**

```markdown
# 週報

## やったこと
- Instagram投稿 3本
- 新メニューの説明文を作成（未公開）
- 打ち合わせ 1件

## 結果
- 問い合わせ 2件
- 打ち合わせ1件が来月開始で合意

## うまくいかなかったこと
- 問い合わせ1件が未返信のまま
- 新メニューの説明文が未公開
- 経理の整理に着手できなかった

## 次にやること
- 未返信の問い合わせに返信する
- 新メニューを公開する
- 経理の整理に着手する
```

「経理が手つかず」を省かず、そのまま「次にやること」に送っている点が大切です。

## うまく使うコツ

- 毎日メモを1行残しておくと、週末に貼り付けるだけで週報になります
- 提出先がある場合は「上司に出す形で」と伝えると、調子が変わります
- 「相談したいこと」は、自分ひとりで事業をしている場合でも書いておくと、後で判断を思い出せます
ご注意

一度に貼り付けるのは1つだけにしてください。いくつも貼ると指示が混ざって、うまく動かなくなります。

別のことをしたくなったら、新しい会話を開いて貼り直してください。

やってみましょう

「打ち合わせメモを整理する」を例に、実際の流れを見てみます。

自分が貼ったメモ
  • 田中さんとの打ち合わせ
  • 新サイトの公開は来月アタマで合意
  • トップの写真、差し替えたいと言われた→誰が用意する？
  • 料金プラン、3つに増やす案が出たけど保留
  • 請求書の宛名、法人名でいいか要確認
返ってきたもの
決まったこと
  • 新サイトの公開時期は来月頭とする
やること
  • トップページの写真を差し替える（担当：未定／期限：未定）
保留・次回持ち越し
  • 料金プランを3つに増やす案
確認が必要なこと
  • トップ写真の素材を用意するのはどちらか
  • 請求書の宛名を法人名にしてよいか

写真の担当者は、メモに書かれていないので「未定」と出ます。 AIが勝手に「田中さんが用意する」と決めないように作ってあります。

議事録は後から「言った・言わない」の証拠になる書類です。 それらしく埋まってしまうと、書類として使えなくなるためです。

毎回貼るのが面倒になったら

気に入って何度も使うようになったら、AIに覚えさせておくこともできます。 一度登録すれば、貼り付けなしで使えます。

ChatGPTの場合

  1. スキルの画面を開く

    左側のメニューから「スキル（Skills）」を開きます。

  2. 新しく追加する

    「新規作成」または「＋」を押して、コピーした中身をそのまま貼り付けて保存します。

  3. あとは話しかけるだけ

    「このメモ整理して」と伝えて、メモを貼れば動きます。

ご注意

パソコン版とスマホ版は、別々に登録が必要です。自動では同期されないため、両方でお使いの場合はそれぞれ登録してください。

Claude（ブラウザ版）の場合

「プロジェクト」を作って、その説明欄に貼り付けて保存してください。 以降、そのプロジェクトの中では貼り付けなしで使えます。

スキルの画面が見当たらない場合もあります。その場合は、これまでどおり貼り付けてお使いください。動作に違いはありません。

パソコンに詳しい方へ

ターミナルをお使いになる方は、Claude Code や Codex にまとめて入れられます。 入れておくと、話しかけるだけで自動的に適切なものが選ばれます。

Claude Code に7つまとめて入れる

npx skills add create-aquarius/business-skills-ja -a claude-code

Codex に入れる

npx skills add create-aquarius/business-skills-ja -a codex

ソースコードは GitHub で公開しています。中身の確認、書き換え、再配布は自由です。

よくある質問

無料のChatGPTでも使えますか

使えます。貼り付けて使う方法なら、プランは問いません。

コピーボタンを押しても反応がないようです

「中身を見る」を開いて、表示された文章を手で全部選択してコピーしてください。同じものが使えます。

7つ全部を一度に貼り付けてもいいですか

おすすめしません。指示が混ざって精度が落ちます。1つの会話につき1つにしてください。

出てきた文章はそのまま使っていいですか

必ずご自身で確認してからお使いください。特に、お客様に送るメールや、販売ページの文章は必ず読み返してください。

問い合わせ返信のスキルは、金額や納期をわざと空欄にして「【要確認：金額】」と出すように作ってあります。そこはご自身で埋めてから送ってください。

自分用に書き換えてもいいですか

はい。自由に書き換えてお使いください。自社の料金表やサービス内容を書き足すと、精度が上がります。

うまくいかないときは

思ったような形で出てこない

貼り付けた文章が、途中で切れていないか確認してください。いちばん上の線で囲まれた部分から、いちばん下まで全部が必要です。

別のことをされてしまう

新しい会話を開いて、もう一度貼り付けてください。同じ会話で長く続けると、前の話に引っ張られることがあります。

途中から言うことを聞かなくなった

会話が長くなると起こります。新しい会話を開いて、貼り直してください。
